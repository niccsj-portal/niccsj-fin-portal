# NICC-SJ Finance & Membership Portal

Volunteer-built finance and membership portal for the **Nigerian Igbo Catholic Community — San Jose**. Static React SPA hosted on GitHub Pages; data, auth, and Row-Level Security live in Supabase.

## 1. Bootstrap (from `docs/technology.md` §16)

Goal: a new volunteer should be running the app in **under 15 minutes** using tools they already know.

### Prerequisites

- **Node.js 20 LTS** and **npm** (no other runtime needed).
- A GitHub account with access to this repository.
- The hosted Supabase **dev** project URL and anon key — ask the System Admin to share them. They are *not* committed to the repo.
- *(Optional)* The **Supabase CLI** if you intend to edit SQL migrations under `supabase/migrations/`. Not required just to run the app.
- *(Not required)* Docker. We use a hosted Supabase dev project instead of a local Postgres stack.

### Steps

```sh
git clone https://github.com/geokwelu/FinanceCouncil.git
cd FinanceCouncil
npm install
cp .env.example .env.local       # fill in the two values shared by the admin
npm run dev                      # http://localhost:5173
```

`.env.local` is git-ignored. Only the two `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` variables are needed; service-role keys and other secrets must never go into any committed env file.

## 2. npm scripts

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server with HMR. |
| `npm run build` | Type-checks (`tsc -b`) then builds the production bundle into `dist/`. |
| `npm run preview` | Serves the built bundle locally for a final sanity check. |
| `npm run lint` | ESLint (flat config) across the whole repo. |
| `npm run typecheck` | TypeScript project references build, no emit. |
| `npm test` | One-shot Vitest run (jsdom, React Testing Library). |
| `npm run test:watch` | Vitest in watch mode. |
| `npm run brand` | Regenerates `public/brand/` derivatives from `public/brand/logo.jpg` (logo PNGs, SVG, favicon, apple-touch-icon). |

CI runs `lint → typecheck → test → build` on every PR and on pushes to non-`main` branches; the deploy workflow builds with the production base path and publishes to GitHub Pages on merge to `main`.

## 4. Environment & deploy notes

- **Local dev** reads `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` from `.env.local` (or your shell env).
- **GitHub Actions deploy** (`.github/workflows/deploy.yml`) reads those same two values from repo `Settings → Secrets and variables → Actions` and builds with `BASE_PATH=/<repo>/` so the SPA is served from the GitHub Pages sub-path. `dist/index.html` is also copied to `dist/404.html` for client-side routing.
- A strict Content Security Policy is injected into `index.html` at build time by the Vite plugin in `src/lib/csp.ts` (per PRD §5 Security).

## 5. Contributing (short version)

- Open a PR against `main`. The `ci.yml` workflow runs lint, typecheck, tests, and build; all four must be green before merge.
- No pre-commit hooks; run `npm run lint`, `npm run typecheck`, and `npm test` locally before pushing.
- Commit messages: free-form, just be descriptive (see `docs/technology.md` §16).
- Sprint scope and "Definition of Done" live in [`docs/PM.md`](docs/PM.md); the story backlog is [`docs/backlog.md`](docs/backlog.md).
- Bug reports and feature requests: open a GitHub Issue against this repo and tag with the matching story ID from the backlog where applicable.
